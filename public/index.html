2. Your run category

Solo Easter Egg speedruns, timed in RTA. The LiveSplit addon detects your map and gum category automatically when your split file identifies them. These choices set your optional therun.gg mapping.

Solo · Easter Egg · RTA. Zetsubou and Super Easter Egg exclude No Gums; Ascension and Shangri-La allow only Any%.

Super Easter Egg setup

Use one continuous LiveSplit file containing Shadows of Evil, The Giant, Der Eisendrache, Zetsubou No Shima, Gorod Krovi, and Revelations last. Name the category Super Easter Egg - Classic Gums - Solo, substituting your gum category. Prefix checkpoints with their map (for example DE - Bow) and end each map with Map - Complete. Keep each map's checkpoints together. Do not reset between maps.

The tracker reads cumulative LiveSplit Real Time, including pauses and resets. The site displays the latest received timer sample; updates can lag by a few seconds. Full instructions are included in the addon download.

Match your split names to shared milestones. Repeated milestones need distinct names.

3. Choose a data source

LiveSplit addon — compatibility update

Download the LiveSplit addon. Close LiveSplit, copy LiveSplit.ZombiesTracker.dll into its Components folder, then reopen it. Add Other → Zombies Tracker in Edit Layout and open its settings.

Paste your private runner key into the addon. Leave map/category on automatic, enable upload, click Apply, and save your layout. For example, name your LiveSplit category Der Eisendrache - No Gums - Solo. Unknown or conflicting maps/categories require an override; multiplayer labels block uploads.

Use only one source per runner. Register on this server to obtain its runner key. If the addon interferes with your LiveSplit layout, remove it and use the optional therun.gg connection while compatibility is checked.

Enter the exact game/category labels displayed on therun.gg. Source labels are matched before recording anything. Your tracker username is separate from the source username; this connection does not verify ownership.

Collects checkpoints observed from now on; does not import lifetime history. Update delays and pause detection depend on the upstream feed.
